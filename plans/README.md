## Findings considered and rejected

- `AVAudioIONode.setVoiceProcessingEnabled`: rejected for this feature because it is a capture/communications path that requires device rendering and both I/O nodes; it cannot process the already-recorded 16 kHz waveform in manual rendering mode.
- Control Center Voice Isolation as the primary implementation: rejected because the public microphone-mode properties are read-only. Pindrop can show the system UI but cannot directly select the user's mode without private APIs.
- RNNoise or WebRTC Audio Processing in the first version: rejected because Apple's public `AUSoundIsolation` covers the macOS 14 deployment target without a native dependency, sample-rate conversion pipeline, bundled model, or license-notice addition.
- Real-time streaming preprocessing in the first version: rejected because production capture uses a raw Core Audio device IO callback and live processing would materially increase concurrency, latency, and route/device risk. Final streaming output already has an offline re-transcription seam.
